1. PROJECT OVERVIEW & PURPOSE
===============================================================================
EduVibe is a full-stack, cloud-native Academic and Learning Management Portal
designed to modernize higher education campus workflows across three key
institutional personas:

1. Students:
   - Self-register with 6-digit email OTP verification.
   - Browse catalog of academic subjects and enroll in courses.
   - Stream recorded lecture videos (.mp4 / .webm) directly inside the browser.
   - Download PDF study notes and syllabus files.
   - Take interactive, timed multiple-choice quizzes with automated grading and instant scoring.
   - Submit assignment files in PDF format.
   - Track personal attendance records with visual alert gauges for the 75% attendance rule.

2. Faculty:
   - Register faculty profile with 6-digit email OTP verification (awaits Admin approval).
   - Create academic courses and view enrolled student rosters.
   - Upload lecture materials (PDF syllabus and video clips up to 100MB).
   - Take daily subject attendance (Present / Absent) by date and subject.
   - Create custom quizzes with configurable time limits, question banks, and point weights.
   - Review and grade student homework submissions with numerical marks and comments.

3. Institutional Administrator:
   - Real-time administrative dashboard displaying total students, faculty, and courses.
   - Review pending faculty registrations and approve accounts with auto-generated
     faculty registration numbers (FAC-2026-XXXX).
   - Maintain the institutional user directory and manage user accounts.

2. REAL ARCHITECTURE & TECHNOLOGIES USED (ACCURATE & VERIFIED)
===============================================================================
This section describes ONLY the technologies, libraries, files, and services
that are actually implemented and present in this repository.

-------------------------------------------------------------------------------
2.1. Frontend: React 18, Vite & Glassmorphism Design System
-------------------------------------------------------------------------------
- Implementation: React 18 SPA bundled with Vite 5.
- Styling: Custom Vanilla CSS design system (`frontend/src/index.css`) featuring
  glassmorphism backdrops (`backdrop-filter: blur`), dark/light theme switching,
  CSS grid dashboards, and reactive animations (zero heavy UI library overhead).
- State Management: `frontend/src/context/AuthContext.jsx` for global authentication,
  session persistence (`localStorage`), JWT decoding, and route guarding.
- Key Files:
  * `frontend/src/App.jsx`: Master client routing and protected route guards.
  * `frontend/src/pages/LoginPage.jsx`: Multi-role login, registration & OTP modals.
  * `frontend/src/pages/StudentDashboard.jsx`: Student course, quiz & attendance UI.
  * `frontend/src/pages/FacultyDashboard.jsx`: Faculty teaching, grading & upload UI.
  * `frontend/src/pages/AdminDashboard.jsx`: Admin approval queue & metrics UI.
  * `frontend/vite.config.js`: Vite dev server configuration with API proxying.

-------------------------------------------------------------------------------
2.2. Backend: Node.js & Express.js REST API
-------------------------------------------------------------------------------
- Implementation: Node.js 20 with Express 4.19 REST API.
- Port: Default port 5000.
- File Upload Handling: Multer disk storage (`backend/middleware/upload.js`) saving
  uploads to `/app/uploads` with cryptographically random hex filenames and MIME
  type/extension whitelisting (up to 100MB).
- Key Files:
  * `backend/server.js`: Express server initialization, CORS, health probe, and metrics exporter.
  * `backend/middleware/auth.js`: JWT token verification and RBAC role authorization.
  * `backend/middleware/upload.js`: Multer file upload security filter.
  * `backend/routes/auth.js`: Registration, login, OTP dispatch, and password resets.
  * `backend/routes/student.js`: Student dashboard, enrollment, quiz & assignment submissions.
  * `backend/routes/faculty.js`: Course creation, material uploads, attendance, quizzes & grading.
  * `backend/routes/admin.js`: Statistics, faculty approval/rejection, user management.

-------------------------------------------------------------------------------
2.3. Database: MongoDB Atlas Cloud M0 & Mongoose ODM
-------------------------------------------------------------------------------
- Implementation: Hosted MongoDB Atlas M0 Free Tier Replica Set (AWS Singapore region).
- Connection String: Configured via `MONGO_URI` environment variable.
- ODM: Mongoose 8.3 with strict schema validation, pre-save password hashing hooks,
  and automatic TTL index expiration.
- Database Models (`backend/models/`):
  * `User.js`: Accounts, Bcrypt hashed passwords, roles (student/faculty/admin), regNumber.
  * `Course.js`: Subjects, departments, enrolled students, uploaded materials (pdf/video).
  * `Attendance.js`: Per-course, per-date presence tracking.
  * `Quiz.js`: Timed quizzes, questions, options, point weights, and student submissions.
  * `Assignment.js`: Homework prompts, deadlines, student file uploads, marks, and feedback.
  * `OTP.js`: 6-digit numeric OTPs with 300-second (5 minute) TTL auto-deletion index.

-------------------------------------------------------------------------------
2.4. Transactional Email Microservice: Resend API
-------------------------------------------------------------------------------
- Implementation: Resend SDK (`resend` npm package).
- Module: `backend/utils/emailService.js`.
- Purpose: Dispatches beautiful HTML transactional emails containing real-time
  6-digit OTP codes for account verification and password resets in `< 2` seconds.
- Fallback: Gracefully logs dev OTP in non-production environments if an API key is missing.

-------------------------------------------------------------------------------

- Verified AWS Resources Created:

  * `aws_security_group.eduvibe_sg`: Firewall rules allowing ports 22 (SSH), 80/443 (HTTP/S), 3005 (Web), 5000 (API), 9090 (Prometheus), 3001 (Grafana).

3. FULL SYSTEM ARCHITECTURE & DATA FLOW
===============================================================================

User Request & Data Lifecycle:
1. Client Access:
   - User opens `https://edu-vibe-lms.vercel.app/`.
   - Vercel's Edge CDN returns the cached React 18 SPA instantly.
2. API & Authentication:
   - When the user registers or logs in, the browser dispatches an API request to `/api/auth/...`.
   - Vercel Edge reverse proxy (`vercel.json`) proxies the request to the live backend:
     `https://eduvibe-lms-backend-api.onrender.com/api/auth/...` (in Mode 4) OR
     `http://<AWS_EC2_IP>:5000/api/auth/...` (in Mode 3).
   - The backend validates input, queries MongoDB Atlas via TLS, verifies passwords using Bcrypt,
     and returns a signed JWT token valid for 7 days.
3. Media File Uploads & Streaming:
   - Faculty uploads lecture notes or video clips through the course dashboard.
   - Multer middleware sanitizes the file name, generates a unique hex suffix, and saves it to `/app/uploads`.
   - Upload metadata (URL, title, timestamp) is committed to MongoDB Atlas.
   - Students download PDFs or stream lecture videos directly via `/uploads/:filename`.
4. Telemetry Scraping:
   - Every API request records latency metrics into Prometheus counters and histograms.
   - Prometheus scrapes `/metrics` every 5 seconds.
   - Grafana queries Prometheus to render real-time request rate and latency graphs.

4. THE FOUR OPERATIONAL EXECUTION MODES (RUN, STOP, DELETE)
===============================================================================

-------------------------------------------------------------------------------
4.1. Mode 1: Local Development (Bare-Metal npm + Vite HMR)
-------------------------------------------------------------------------------
Best for rapid code editing with sub-second hot module replacement.

Prerequisites: Node.js 20+ and npm installed.

A. RUN Commands:
   1. Setup environment files:
      cp .env.example .env
      cp backend/.env.example backend/.env
   2. Terminal 1 (Start Backend API):
      cd backend
      npm install
      npm run dev
      (Runs on http://localhost:5000)
   3. Terminal 2 (Start React Frontend):
      cd frontend
      npm install
      npm run dev
      (Runs on http://localhost:5173)

B. STOP Commands:
   - Press Ctrl + C in both terminal windows.

C. DELETE / WIPE Commands:
   - Delete installed dependencies: Remove-Item -Recurse -Force backend/node_modules, frontend/node_modules
   - Clear local uploaded files: Remove-Item -Recurse -Force backend/uploads/*

-------------------------------------------------------------------------------
4.2. Mode 2A: Containerized Desktop (Docker Compose 4-Container Stack)
-------------------------------------------------------------------------------
Best for running the entire application and observability stack locally in Docker.

Prerequisites: Docker Desktop installed and running.

A. RUN Commands:
   # Start core application (Frontend + Backend):
   docker compose up -d

   # OR start full stack with Prometheus and Grafana:
   docker compose --profile monitoring up -d

   Access Endpoints:
   - Frontend Web App:     http://localhost:3005
   - Backend API Health:   http://localhost:5000/api/health
   - Prometheus Metrics:   http://localhost:5000/metrics
   - Prometheus Collector: http://localhost:9090
   - Grafana Dashboard:    http://localhost:3001

B. STOP Commands:
   docker compose --profile monitoring down
   (Safely preserves uploaded PDFs and videos in uploads_data volume).

C. DELETE / WIPE Commands:
   # Destroy containers and wipe persistent uploaded files:
   docker compose down -v --rmi all

   # Reclaim all Docker disk space:
   docker system prune -a --volumes -f

-------------------------------------------------------------------------------
4.3. Mode 2B: Local Cloud-Native Orchestration (Minikube Kubernetes)
-------------------------------------------------------------------------------
Best for testing production-grade Kubernetes orchestration with 5 load-balanced Pods.

Prerequisites: Minikube and kubectl installed.

A. RUN Commands:
   1. Start Minikube cluster:
      minikube start --driver=docker
   2. Point terminal Docker CLI to Minikube registry:
      minikube docker-env | Invoke-Expression
   3. Build container images inside Minikube:
      docker build -t eduvibe-backend:latest ./backend
      docker build -t eduvibe-frontend:latest ./frontend
   4. Create namespace & inject environment secrets:
      kubectl apply -f devops/k8s/namespace.yaml
      kubectl create secret generic eduvibe-secrets --namespace=eduvibe --from-env-file=".env" --dry-run=client -o yaml | kubectl apply -f -
   5. Deploy manifests:
      kubectl apply -f devops/k8s/backend.yaml
      kubectl apply -f devops/k8s/frontend.yaml
      kubectl apply -f devops/k8s/monitoring.yaml
   6. Port-forward access:
      kubectl port-forward svc/frontend -n eduvibe 3006:80
      (Web portal opens at http://localhost:3006)
      kubectl port-forward svc/grafana -n eduvibe 3002:3000
      (Grafana opens at http://localhost:3002)

B. STOP Commands:
   # Safely pause the cluster VM:
   minikube stop

   # OR scale backend pods to zero to free RAM:
   kubectl scale deploy/backend --replicas=0 -n eduvibe

C. DELETE / WIPE Commands:
   # Delete the application namespace:
   kubectl delete namespace eduvibe

   # Delete entire local Minikube cluster VM:
   minikube delete

-------------------------------------------------------------------------------
5.1. Authentication Routes (/api/auth)
-------------------------------------------------------------------------------
- POST /api/auth/send-otp
  Body: { email: string, purpose: 'registration' | 'password_reset' }
  Desc: Dispatches 6-digit verification code via Resend API (valid for 5 minutes).

- POST /api/auth/register-student
  Body: { name, email, password, phone, address, department, courseName, otp }
  Desc: Verifies OTP, hashes password with Bcrypt, and creates active student with regNumber (STU-2026-XXXX).

- POST /api/auth/register-faculty
  Body: { name, email, password, phone, address, department, courseName, otp }
  Desc: Verifies OTP, hashes password, and creates faculty account pending Admin approval (`isApproved: false`).

- POST /api/auth/register-admin
  Body: { name, email, password, phone, address, department }
  Desc: Registers master system administrator (strictly allowed only if no admin exists).

- POST /api/auth/login
  Body: { email, password, role }
  Desc: Rate-limited authentication checking Bcrypt hash and issuing 7-day signed JWT token.

- POST /api/auth/reset-password
  Body: { email, otp, newPassword }
  Desc: Validates OTP and updates user password with Bcrypt encryption.

- GET /api/auth/me
  Headers: { Authorization: "Bearer <token>" }
  Desc: Returns current authenticated user profile without password hash.

-------------------------------------------------------------------------------
5.2. Student Routes (/api/student)
-------------------------------------------------------------------------------
Protected: Requires JWT token with role = 'student'.

- GET /api/student/dashboard
  Desc: Returns summary KPIs, enrolled courses, attendance overview, and upcoming quizzes.

- GET /api/student/courses
  Desc: Fetches all institutional courses available for enrollment.

- POST /api/student/courses/:id/enroll
  Desc: Enrolls student in course :id and adds student ID to course enrolledStudents list.

- GET /api/student/quizzes
  Desc: Returns all available quizzes for enrolled courses.

- POST /api/student/quizzes/:id/submit
  Body: { answers: [number] }

- GET /api/student/assignments
  Desc: Retrieves all pending and submitted assignments for enrolled courses.

- POST /api/student/assignments/:id/submit
  Body: FormData with file `submissionFile` (PDF)
  Desc: Uploads student assignment PDF, updates submission record with timestamp.

- GET /api/student/attendance
  Desc: Returns detailed per-subject attendance percentages with 75% warning status.

5.3. Faculty Routes (/api/faculty)

Protected: Requires JWT token with role = 'faculty' (and `isApproved: true`).

- POST /api/faculty/attendance
  Body: { courseId, date, records: [{ studentId, status: 'present' | 'absent' }] }

- GET /api/faculty/attendance/:courseId
  Desc: Retrieves historical attendance records for course :courseId.

- POST /api/faculty/quizzes
  Body: { title, courseId, durationMinutes, questions }

- GET /api/faculty/quizzes
  Desc: Lists all quizzes created by this faculty member with student score summaries.

- POST /api/faculty/assignments
  Body: FormData with optional `attachment` file (PDF prompt)
  Desc: Creates a homework assignment with due date and maximum marks.

- GET /api/faculty/assignments
  Desc: Lists all faculty assignments and received student submissions.

- POST /api/faculty/assignments/:assignmentId/grade/:submissionId
  Body: { marks, feedback }

6. DATABASE SCHEMAS & DATA MODELS
===============================================================================

1. User Model (`backend/models/User.js`):
   - name: String (required, trimmed)
   - email: String (required, unique, lowercase)
   - password: String (required, Bcrypt hash with salt round 10)
   - role: Enum ['student', 'faculty', 'admin'] (default: 'student')
   - regNumber: String (unique, sparse - STU-2026-XXXX or FAC-2026-XXXX)
   - phone: String (optional)
   - address: String (optional)
   - department: String (default: 'Computer Science')
   - courseName: String (optional)
   - isApproved: Boolean (true for student/admin; false for faculty until approved)
   - enrolledCourses: [ObjectId -> Course]
   - timestamps: true

2. Course Model (`backend/models/Course.js`):
   - title: String (required, trimmed)
   - code: String (required, unique, uppercase, e.g. CS301)
   - department: String (required, default: 'Computer Science')
   - description: String
   - faculty: ObjectId -> User (required)
   - enrolledStudents: [ObjectId -> User]
   - materials: [{ title, type: 'pdf'|'video', fileUrl, uploadedAt }]
   - timestamps: true

3. Attendance Model (`backend/models/Attendance.js`):
   - course: ObjectId -> Course (required)
   - faculty: ObjectId -> User (required)
   - date: String (YYYY-MM-DD format for fast querying)

8. ENTERPRISE SECURITY & DEVSECOPS HARDENING
===============================================================================
1. Zero Hardcoded Credentials:
   All credentials (database URIs, JWT secrets, passwords, Resend API keys) are
   injected strictly via `.env`, Kubernetes Secrets (`secretKeyRef`), or GitHub Secrets.
2. Password Protection:
   Bcrypt with 10 salt rounds hashes passwords before database persistence. User
   models enforce `select('-password')` by default on all queries.
3. NoSQL Operator Injection Defense:
   Authentication routes strictly validate types (`typeof string`) on incoming fields,
   defeating MongoDB operator injection attacks (`{"$gt": ""}`).
4. Anti-Brute-Force Rate Limiting:
   In-memory sliding window rate limiter protects `/api/auth` endpoints (maximum
   20 requests per 15-minute window per client IP).
5. File Upload Sanitation:
   Multer middleware generates cryptographically random 12-byte hex suffixes,
   strips path traversal tokens, validates extensions and MIME types, and limits
   file sizes to 100MB.
6. Container Hardening:
   `backend/Dockerfile` runs under non-root `USER node` to prevent container breakout.
   `frontend/Dockerfile` utilizes multi-stage compilation to isolate build dependencies.
7. Cloud Cost & Security Governance:
   Terraform provisions encrypted 20 GB gp3 storage volumes with KMS encryption,
   restricts ingress ports via Security Groups, and adheres strictly to $0.00 Free Tier limits.

9. OPERATIONAL TROUBLESHOOTING CHEAT SHEET
===============================================================================

Issue 1: Port 5000 Already In Use (listen EADDRINUSE :5000)
- Cause: A previous Node.js process or Docker container is already binding port 5000.
- Resolution (PowerShell):
  Get-NetTCPConnection -LocalPort 5000
  Stop-Process -Id <PID> -Force

Issue 2: MongoDB Connection Error (MongooseServerSelectionError)
- Cause: Host cannot reach MongoDB Atlas cluster due to IP access whitelist or network drop.
- Resolution:
  1. Verify Internet connectivity.
  2. Log into MongoDB Atlas (cloud.mongodb.com) ➔ Security ➔ Network Access.
  3. Ensure IP Whitelist includes `0.0.0.0/0` (allow access from anywhere for cloud deployment).
  4. Ensure `MONGO_URI` in `.env` is correct.

Issue 3: Nginx 502 Bad Gateway / JSON Parse Error ("Unexpected token < in JSON")
- Cause: Nginx reverse proxy cached an old backend container IP after a container restart.
- Resolution:
  In `frontend/nginx.conf`, the directive `resolver 127.0.0.11 valid=10s ipv6=off;`
  ensures Nginx refreshes DNS dynamically every 10 seconds.
  Execute: `docker restart eduvibe-frontend`

Issue 4: Docker Container OOMKilled on AWS EC2
- Cause: Compiling frontend or running large builds on a 1GB RAM t2.micro machine exhausts memory.
- Resolution:
  The Terraform `user_data.sh` script automatically configures a 2GB Linux swapfile:
  `fallocate -l 2G /swapfile && mkswap /swapfile && swapon /swapfile`
  Additionally, GitHub Actions builds and validates containers in GitHub Cloud runners,
  completely offloading build memory from the EC2 instance.

Issue 5: EC2 Public IP Changes After Stop/Start
- Cause: AWS standard public IPv4 addresses rotate upon EC2 instance reboot.
- Resolution:
  The GitHub Actions CI/CD workflow (`.github/workflows/deploy.yml`) queries AWS EC2 API
  dynamically via the project tag `Name=eduvibe-cloud-server` upon every git push,
  auto-discovering the new public IP with zero manual configuration.
